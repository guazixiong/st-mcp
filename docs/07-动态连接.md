# 动态连接：一个 ST-MCP 实例连多个神通库

默认部署是一个实例连一个库。开启动态连接后，**同一个进程、同一个端口**可以按请求
切换到任意一台在白名单里的神通数据库：客户端每次请求带上目标库的 IP、端口、账号，
服务端就用这套信息建立（或复用）连接，用完把连接留在池里给同一目标的下次请求。

目标来源有三档，优先级从高到低：

1. 租户 token（`/mcp/<token>`、`Authorization: Bearer <token>`、`X-ST-Token`）——
   来自 `tenants.json`，账号固定；
2. 请求里的动态目标（本文）；
3. 进程自己的默认库（`ST_HOST/ST_PORT/ST_USER/ST_PASSWORD/ST_DB`）。

动态目标**永远覆盖不了 token**：带 token 的请求即使同时带了 `X-ST-DB-*`，也按 token 走。

## 三种写法

### 1. 分字段请求头

| 头 | 含义 | 缺省 |
|---|---|---|
| `X-ST-DB-Host` | IP 或主机名（必填） | — |
| `X-ST-DB-Port` | 端口 | `ST_DYNAMIC_DEFAULT_PORT`（2003） |
| `X-ST-DB-User` | 账号（必填） | — |
| `X-ST-DB-Password` | 口令（必填） | — |
| `X-ST-DB-Name` | 库名 | `ST_DYNAMIC_DEFAULT_DB`（OSRDB） |

```bash
curl -X POST http://server:8100/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H 'X-ST-DB-Host: 10.0.0.21' \
  -H 'X-ST-DB-Port: 2003' \
  -H 'X-ST-DB-User: APP' \
  -H 'X-ST-DB-Password: secret' \
  -H 'X-ST-DB-Name: OSRDB' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"demo","version":"1"}}}'
```

### 2. 单个 JSON 头 `X-ST-DB`

```text
X-ST-DB: {"host":"10.0.0.21","port":2003,"user":"APP","password":"secret","database":"OSRDB"}
```

或 base64url 编码后（去掉末尾 `=`）：

```bash
BLOB=$(printf '%s' '{"host":"10.0.0.21","port":2003,"user":"APP","password":"secret","database":"OSRDB"}' \
  | base64 -w0 | tr '+/' '-_' | tr -d '=')
curl ... -H "X-ST-DB: $BLOB" ...
```

> **口令含中文时必须用这种形式或 URL 形式。** HTTP 头值只能是 latin-1，
> `X-ST-DB-Password` 里放 UTF-8 中文会在客户端就抛 `UnicodeEncodeError`，
> 请求根本发不出去。JSON/base64 头是 ASCII，没有这个问题。

### 3. URL 查询参数

```text
http://server:8100/mcp?st_host=10.0.0.21&st_port=2003&st_user=APP&st_password=secret&st_db=OSRDB
```

或 `?st=<base64url(JSON)>`。URL 里非 ASCII 口令要先 percent-encode（UTF-8）。

**优先级**：`X-ST-DB` > `X-ST-DB-*` 分字段 > URL 查询。只取一处，不混合拼接；
需要自定义端口/库时把整组字段带上或让它们走默认值。

第一次 `initialize` 请求里的目标会绑定到这个 `Mcp-Session-Id`，之后同一会话的
`tools/call` 即使不再带头，也会继续用这个目标（会话绑定）。

## 白名单（默认拒绝）

```ini
ST_DYNAMIC_ENABLED=yes
ST_DYNAMIC_ALLOW=127.0.0.1,10.0.0.0/24,*.corp.example
ST_DYNAMIC_ALLOW_PORTS=2003
ST_DYNAMIC_ALLOW_DEFAULT=no
ST_MAX_TARGETS=16
```

- `ST_DYNAMIC_ALLOW`：逗号分隔，支持精确主机、CIDR、`*.后缀`、`*`；留空 = 全部拒绝。
- `ST_DYNAMIC_ALLOW_PORTS`：逗号分隔或 `*`；留空 = 全部放行（不建议）。
- `ST_DYNAMIC_ALLOW_DEFAULT=no`：没有任何目标信息的请求直接 401，防止陌生人白用默认账号；
  设成 `yes` 才会回落到 `ST_*` 默认库。
- `ST_DYNAMIC_ACCESS_MODE`：动态目标的 SQL 权限，`restricted` 只读；留空跟随 `ACCESS_MODE`。
- `ST_MAX_TARGETS`：连接池上限（按目标身份 LRU 淘汰，默认 16）。

白名单校验发生在建立连接**之前**。不在名单里的主机返回 403，字段缺失/端口非法返回 400，
两者都不会触发任何数据库连接。

## 容器里的 `127.0.0.1`

容器不是宿主机，容器内的 `127.0.0.1` 是容器自己。服务端把动态目标里的
`127.0.0.1 / localhost / ::1` 自动改写成 `ST_HOST_GATEWAY`（默认 `172.17.0.1`，
即宿主机在默认 bridge 网络里的地址），与 `deploy.conf` 里 `ST_HOST=127.0.0.1` 的行为一致。
宿主机上的神通监听 `0.0.0.0:2003` 时可以直接这么用；只监听 `127.0.0.1` 时容器连不上，
要么让库监听 `0.0.0.0`，要么用 `--network host` 起容器。

## 连接池与身份

池键是 `sha256(host, port, user, password, database)` 的前 16 位。口令变了就是新目标，
不会拿旧连接去连；同一目标的高频请求共用一个池。`ST_MAX_TARGETS` 满后按最近最少使用淘汰，
淘汰时关闭连接。

## 状态码速查

| 情况 | HTTP |
|---|---|
| 请求带了合法目标 / 会话已绑定 | 200 |
| 没有任何目标、没有 token，且 `ALLOW_DEFAULT=no` | 401 |
| 目标主机或端口不在白名单 | 403 |
| 目标字段缺失、端口非法、JSON/base64 解不开 | 400 |
| 目标合法但数据库连不上（口令错、库没起） | 200 + 工具结果里的 `Error:` |

最后一行是 MCP 的语义：协议层成功，业务错误放在 `tools/call` 的结果文本里。
判断数据库是否真的能查，要看 `execute_sql` 的返回内容，不要只看 HTTP 状态码。

## 验证

```bash
# 单元测试（不需要数据库）
python -m pytest src/test/test_dynamic.py -q

# 真机协议 + 数据库（需要 secrets/st-mcp.env 里的口令）
python3 scripts/probe-dynamic.py --base http://127.0.0.1:8100
```

Windows 包里的 `验收检查.bat` 会跑同一组协议检查；`execute_sql` 那一项需要机器上
装了神通 Windows 客户端（`ACI.dll`），否则显示 SKIP。
